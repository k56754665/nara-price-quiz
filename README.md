# 이게 얼마게? — 나라장터 가격 퀴즈

조달청 공식 API로 검증한 등록 계약단가 10개를 맞히는 한국어 웹게임입니다. 가격 기준일은 **2026-11-03**입니다.

## 플레이 흐름

1. 나라장터에 등록된 실제 상품 사진·제품 이미지와 규격을 살펴봅니다.
2. 첫 추측이 틀리면 정답을 숨기고 UP/DOWN과 ‘아주 조금·조금·꽤·많이·아주 많이’ 차이 힌트를 표시합니다.
3. 한 번 더 추측합니다. 첫 정답은 즉시 결과로, 두 번째 추측은 맞고 틀림에 관계없이 결과로 진행합니다.
4. 정답·점수·틈새 지식을 한 결과 화면에서 확인하고 다음 물건으로 이동합니다.
5. 최종 결과표에서 두 번의 추측, 점수, 사진, 틈새 지식 9개를 함께 돌아봅니다.

혼자 플레이만 지원합니다. 점수는 마지막 추측에 따라 계산하며, 정확한 정답만 1,000점입니다. 45초 모드에서는 시도마다 45초가 주어지고, 첫 시간초과에는 방향 힌트 없이 한 번 더 기회를 제공합니다.

진행 상황·첫 추측·힌트는 이 브라우저에 저장됩니다. 이전 다인용 버전의 진행 데이터는 새 플레이에 불러오지 않습니다. 결과 복사, JSON 저장, 키보드 입력, 선택형 효과음, 전체 화면, 모바일 레이아웃을 지원합니다.

## 로컬 실행과 검사

외부 패키지 설치 없이 Node.js로 실행합니다.

```powershell
npm run dev
```

`http://127.0.0.1:4173/`에서 플레이합니다. 로컬 서버는 `dist/` 아래 파일만 제공합니다.

```powershell
npm run check
```

가격 입력, UP/DOWN과 거리 힌트, 두 시도 상태의 복구, 마지막 추측 기준 점수, 시간초과, 가격·단위·인도조건, 상품 이미지 체크섬과 출처, 틈새 지식 연결을 검사합니다.

## 데이터와 이미지

`dist/data.json`은 상위 `research/episode_10_2026-11-03.json`에서 가져온 검증 데이터를 사용합니다. 계약번호·순번·규격·단위·인도조건·조회일을 보존하며, 정답은 `cntrctPrceAmt`에 해당하는 등록 계약단가입니다. 실제 구매·지급총액이 아닙니다. 당시 활성 할인 정보가 있던 C11·C16은 출제하지 않습니다.

상품 이미지는 각 물품식별번호에 연결된 공식 API의 `prdctImgUrl`에서 받았습니다. `image-sources.json`에 모델·출처 URL·원문 체크섬을 보관하고, 게임의 이미지 크게 보기와 계약 정보에 원본 링크를 제공합니다. 원본을 수정하지 않았습니다. 그네와 조합놀이대는 공급업체가 등록한 제품 표현 이미지이며 실사 사진으로 표시하지 않습니다.

API 키, 담당자 연락처, 인증이 포함된 요청 URL은 배포 파일에 없습니다. 상품 이미지를 배포에 포함하므로 외부 이미지 서버에 연결하지 않아도 플레이 화면이 표시됩니다.

## 온라인 랭킹 (Supabase)

결과 화면에서 닉네임을 입력해 기록을 등록하고, 처음 화면의 **온라인 랭킹 보기**에서 모드별 TOP 20을 볼 수 있습니다. 설정이 비어 있으면 랭킹 UI가 숨겨지고 게임은 그대로 동작합니다.

### 켜는 방법

1. [supabase.com](https://supabase.com)에서 새 프로젝트를 만듭니다. 무료 요금제로 충분합니다.
2. 대시보드 **SQL Editor**에 [`supabase/leaderboard.sql`](supabase/leaderboard.sql) 전체를 붙여 넣고 실행합니다. 다시 실행해도 안전합니다.
3. **Project Settings → API**에서 Project URL과 `anon` `public` 키를 복사해 [`dist/leaderboard-config.js`](dist/leaderboard-config.js)에 넣습니다. `anon` 키는 공개용이라 저장소에 올려도 됩니다. **`service_role` 키는 절대 넣지 마세요.** 테스트가 이를 검사합니다.
4. `npm run check` 통과 후 `main`에 올리면 GitHub Pages에 반영됩니다.

### 공정성 규칙

- 브라우저는 라운드별 추측값만 보냅니다. 점수는 Supabase 함수가 서버의 정답표로 다시 계산합니다.
- 테이블은 RLS로 잠겨 있어 브라우저에서 직접 읽거나 쓸 수 없고, `submit_score`·`get_leaderboard` 함수만 호출할 수 있습니다.
- 정답이 라운드마다 공개되므로, 모드별로 **처음 시작한 게임**만 등록할 수 있습니다. 서버도 기기 ID당 모드별 한 번만 받습니다.
- 정답이 `data.json`에 포함된 캐주얼 퀴즈이므로 작정한 조작(코드를 고쳐 만점 제출, 저장소를 지워 새 기기로 위장)까지 막지는 못합니다. 이상한 기록은 Supabase **Table Editor**의 `leaderboard_scores`에서 지우면 됩니다.
- 문제 세트를 바꾸면 SQL의 `quiz_answers`에 새 `question_set`(= `data.json`의 `referenceDate`) 정답을 추가하세요. 랭킹은 문제 세트별로 따로 집계됩니다.

## 배포

GitHub Pages에서는 `.github/workflows/pages.yml`이 `main`에 대한 푸시 또는 수동 실행을 받아 검사를 수행한 뒤 `dist/`만 배포합니다. 별도 패키지 설치나 API 키 설정이 필요하지 않습니다. GitHub 저장소의 **Settings → Pages → Source → GitHub Actions**를 한 번 선택해야 합니다. 배포 결과 링크는 **Actions → Deploy game to GitHub Pages**에서 확인합니다.

게임의 CSS·스크립트·데이터·이미지는 상대 경로를 사용하므로 프로젝트 주소의 하위 경로에서도 동작합니다. 소스 수정 후 `npm run check`를 통과하고 `main`으로 올리면 같은 게임 링크가 갱신됩니다. GitHub Actions에는 `dist/`만 사이트 산출물로 전달하며 `.env.local`은 필요하지 않습니다.

기존 Sites 배포의 정적 디렉터리도 `dist`입니다. 로컬 `.openai/hosting.json`은 해당 호스팅 연결 정보이며 GitHub 공개 소스 패키지에는 포함하지 않습니다.

공개·촬영 직전에 같은 계약 행을 재조회하거나, 게임이 2026-11-03 스냅샷임을 표시해야 합니다. 정답이 프런트엔드 데이터에 포함되는 캐주얼 퀴즈이며 경쟁형 대회용 부정행위 방지는 별도 기능입니다.
