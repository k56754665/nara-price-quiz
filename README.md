# 이게 얼마게? — 나라장터 가격 퀴즈

나라장터에서 수집한 상품을 사람이 선별하고, 승인한 문제은행에서 매 게임 무작위로 출제하는 정적 웹게임입니다. 최초 30개는 2026-11-03 자료로 시작했으며, 로컬 선별실에서 새 후보 수집과 현재 계약 정보 갱신을 지원합니다. 게임 중 나라장터 API를 호출하지 않습니다.

2026-11-09 선정 완료한 **104개**를 현재 문제은행에 반영했습니다. 문제·로컬 이미지·랭킹 정답표·이미지 출처 목록을 같은 승인 목록에서 생성합니다. 14개는 최종 재조회가 API 호출 제한(429)으로 실패해 당일 앞서 성공한 조회 스냅샷을 사용했으며, 각 문제의 실제 `checkedAt`과 후보의 실패 이력을 그대로 보존했습니다. 이를 새 조회 성공으로 표시하지 않습니다.

## 수집·갱신·반영 버튼

| 버튼 | 실제 동작 |
| --- | --- |
| 아직 안 본 종류 찾기 | 등록한 검색 계획 안에서 한 번도 보지 않은 종류만 조회합니다. 승인·보류·제외·미검토 이력이 있는 종류는 제조사·모델·가격이 달라도 자동으로 다시 채우지 않습니다. |
| 승인 상품 최신 정보 갱신 | 승인한 모든 상품을 물품식별번호로 재조회하고, 같은 계약번호·순번·단위·인도조건을 확인합니다. 가격·규격 변경을 카드에 표시하며 선택 상태와 기존 게임은 유지합니다. |
| 검증 후 게임에 반영 | 승인 목록을 다시 실조회하고 이미지까지 확인한 뒤 게임 데이터와 랭킹 SQL을 함께 생성합니다. 확인 실패가 있으면 기존 게임을 유지합니다. |

새 후보는 자동 승인되지 않습니다. 승인 100개는 문제은행의 첫 확보 목표이며, 한 번의 수집량은 기본 20종·많이 30종·절약 10종 목표입니다. 비슷한 모델로 개수를 채우지 않고 실제 저장된 새로운 종류 수를 표시합니다. 다음 클릭은 저장된 수집 위치에서 이어집니다. 등록한 검색 계획 밖의 물건을 자동 발굴하는 기능은 없습니다. 저장 응답에 처음 보는 종류가 있으면 먼저 후보로 추가하고, 추가 가격 API 조회 없이 반환합니다.

같은 종류는 제조사·모델번호·크기·색상이 달라도 대표 1개만 수집합니다. 이미 승인·보류·제외했거나 선별실에 있는 종류의 다른 모델은 다시 채우지 않습니다. 명시적으로 용도가 다른 장갑·로봇 등은 별도 종류로 구분하며, 동일 이미지 주소·체크섬도 중복으로 걸러냅니다. 서비스·용역·임대 상품과 흔한 사무 소모품보다 실물 특수장비를 우선합니다. 종류 구분은 규격명의 물품명과 명시된 용도에 따른 규칙이므로 완벽한 시각적 판정은 아닙니다. 이미 사람이 승인한 모델들은 자동으로 합치거나 삭제하지 않습니다.

**제외**는 목록에서 바로 숨깁니다. 제외 보관함 탭은 제공하지 않고, 같은 상품의 재등장을 막기 위한 물품식별번호 이력과 기존 선택 자료만 내부에 보존합니다. **미검토 모두 제외**와 **선택 제외**는 변경 전 선택을 .artifacts/review-backups/에 백업합니다. 승인·보류·메모·기존 게임은 보존합니다.

새 종류 수집에서는 제외 이력이 있는 종류도 이미 본 종류로 처리합니다. 다른 제조사·모델의 같은 물건을 원할 때는 현재 후보의 **대표 상품 비교**에서 명시적으로 선택합니다. 종류를 판정하는 규칙이 바뀌어도 후보에 저장된 원래 종류 ID는 재수집 방지에 사용합니다.

카드에는 품목별 최종 확인 시각, 최근 변경 전후 값, 조회 실패 사유를 표시합니다. 조회에 실패하면 이전 조회 시각을 갱신하지 않습니다. 최신 가격은 조회 시점 API가 반환한 해당 계약 행의 등록 계약단가이며, 실제 지급총액이나 할인 적용 구매액을 뜻하지 않습니다.

수집·갱신은 로컬 .env.local 또는 상위 폴더 .env.local의 DATA_GO_KR_SERVICE_KEY를 사용합니다. 인증키는 브라우저·후보 파일·배포 산출물에 포함하지 않습니다. 원 API의 담당자 이름·전화번호·이메일도 후보 파일에 저장하지 않습니다. 인터넷 사용이 허용된 터미널에서 서버를 실행해야 합니다.

작업 진행률은 화면에 표시되며, 같은 서버가 실행 중이면 화면을 새로고침해도 실행 중인 작업에 다시 연결합니다. 수집·갱신 중 중복 작업과 선택 변경은 잠시 막지만, 게임·테스트 랭킹은 계속 사용할 수 있습니다.

## 로컬 선별과 미리보기

```powershell
npm run curate
```

- 선별실: http://127.0.0.1:4174/admin/
- 게임 미리보기: http://127.0.0.1:4174/

브랜치나 푸시 없이 로컬 미리보기가 가능합니다. 작업을 분리하려면 기능 브랜치에서 검토하고, 확인이 끝난 뒤 main에 병합하세요. 현재 배포 워크플로는 main 푸시에서 동작합니다.

1. 후보 카드의 사진·가격·규격·단위·인도조건을 확인합니다. 사진을 누르면 크게 볼 수 있습니다.
2. **먼저 볼 후보**부터 사진·규격을 확인합니다. 체크박스나 **이 목록의 추천 후보 선택**으로 화면에 표시된 후보를 선택하고 **선택 승인 / 선택 제외**로 한 번에 최대 100개를 처리합니다. 개별 승인·보류·제외와 메모도 지원합니다. 선택은 content/review.json에 저장되며, 메모는 입력 후 잠시 뒤 자동 저장됩니다. 승인·제외 후 전체 가격 자료를 다시 읽지 않고 변경된 선택만 반영합니다. 카드는 한 번에 24개씩 표시하며 더 보기로 이어갑니다. 승인 목표는 100개이고 상한은 아닙니다.
3. **검증 후 게임에 반영**을 누릅니다. 최소 3개가 필요하며, 승인된 문제와 로컬 이미지만 새 게임에 사용합니다. 할인 정보는 정답 계산에 반영하지 않으며, 해당 카드와 게임 문제에 이 기준을 표시합니다. 반영 실패 시 기존 문제은행이 유지됩니다.
4. 게임 미리보기 탭을 새로고침하고 새 게임을 시작합니다. 기존 게임은 저장된 문제·가격·순서로 이어집니다.

처음에는 기존 게임의 10개를 승인 상태로 가져왔고 나머지 20개는 보류 상태로 시작했습니다. 이후의 사람 선택은 보존합니다. 후보 이미지는 로컬에 저장하고, 변경된 이미지는 별도 파일로 보존해 이전 이어하기 화면을 유지합니다. 관리 화면과 후보 원본은 dist 밖에 있어 공개 사이트에 배포되지 않습니다.

로컬 서버는 127.0.0.1에서만 듣습니다. **로컬 게임의 랭킹은 이 PC의 테스트 기록**이며 운영 Supabase에는 요청하지 않습니다. 테스트 기록은 .artifacts/preview-scores.json에 저장합니다. 서버를 다시 시작하려면 Ctrl+C 후 같은 명령을 실행하세요.

새 후보의 **비교 후보 · 대표 고르기**에서 제조사가 다른 최대 5개 상품의 사진·가격·규격을 확인합니다. 설치·부가세·완제품 단위와 용도를 맞추며, 시소는 정원도 구분합니다. 놀이터 기구는 기준 상품의 각 치수 ±35% 범위로 비교하고, 농구대의 고정/이동/벽부착 방식과 차단기의 번호인식·전광판·LED 기능을 분리합니다. 비상구 유도등은 이번 출제 범위를 피난구용·10W 이하로 정했으며 터널·고출력·통로용을 구분합니다. 10W는 시세나 법정 기준이 아닌 검색 범위 설정입니다. 세부 재질·크기·배터리 등 응답에 없는 규격은 사진과 규격서를 직접 검토해야 합니다.

한 제조사의 여러 모델이 중앙값에 더 큰 영향을 주지 않도록 제조사마다 실제 대표 상품 1개씩 계산합니다. 비교 가능한 제조사가 3곳 이상일 때 중앙값에 가까운 실제 상품을 추천하며, 중앙값 자체를 게임 정답으로 사용하지 않습니다. 3곳 미만이면 자료 부족으로 표시합니다. 저장 응답 일부의 비교 결과이므로 전체 시장 시세로 해석하지 않습니다.

다른 대표를 선택하면 기존 미검토 후보는 메모를 보존하고 보류로 이동하며, 선택한 상품은 미검토로 저장합니다. 등록 사진만 필요할 때 내려받고 가격 API는 호출하지 않습니다. 기존 승인·보류·제외는 비교 화면에서 자동 교체하지 않습니다. 새 비교 후보는 같은 종류에서 대표 1개만 승인할 수 있습니다.

**먼저 볼 후보**는 최신 계약 행·사진·단위가 있고 제조사 3곳 이상을 비교했으며 가격·범위 경고가 없는 미검토 상품입니다. 부족한 비교 근거, 범위 불일치, 부품/완제품 이름 불일치, 묶음 단위, 오래된 자료는 **확인 필요**로 표시합니다. 중앙값의 1.75배 이상 또는 1/1.75 미만, 비교 가격 차이 3배 초과, 세부 규격을 넓힌 동일 종류 참고 가격과 4배 넘는 차이는 검토 사유로 표시합니다. 가격·범위 경고가 있는 상품을 승인하려면 확인 근거를 메모에 남깁니다. 넓힌 비교는 규격이 달라 시세로 쓰지 않습니다. 이 기준은 검토 우선순위이며 API 원본 가격의 정확성이나 적정 시세를 보증하지 않습니다. 원본 가격을 임의로 낮추거나 자동 승인하지 않습니다. 일괄 처리는 모든 항목을 검증한 뒤 한 번 저장하므로 일부만 승인되는 것을 막습니다.

**아직 안 본 종류 찾기**는 등록한 전체 검색 계획(현재 294종)과 저장 응답을 이용합니다. 한 번에 찾을 양은 기본(새 종류 20종 목표·가격 API 최대 30회), 많이(30종 목표·최대 50회), 절약(10종 목표·최대 10회) 중 선택하며, 선택은 이 브라우저에 저장됩니다. 목표에 도달하면 조회 상한 전에 멈추고, 결과가 없거나 조건이 맞지 않으면 목표보다 적게 추가될 수 있습니다. 같은 종류의 모델은 대표 1개만 추가합니다. 0건 응답도 당일 재사용하고 미탐색 종류·대체 검색어·다른 계약 유형으로 이어가며, 키워드별 최대 3페이지까지 탐색합니다. 검색 목록을 모두 확인하면 목록 추가 알림을 표시하고 반복 실행을 차단합니다. 완료 안내에는 실제 조회 횟수·받은 행 수·추가된 종류 수·남은 검색 조건을 구분합니다. 승인 상품 갱신·게임 반영의 검증 조회는 이 수집 한도와 별도입니다.

게임만 확인하려면 기존 명령 `npm run dev`를 사용합니다(http://127.0.0.1:4173/). 이 명령도 테스트 랭킹을 사용하며 관리 화면은 열지 않습니다. 카카오 공유는 기존 키와 SDK를 유지합니다. 실제 공유창은 개발자 콘솔에 등록된 도메인에서 확인해야 하며, 4174를 사용하려면 그 origin의 등록 여부를 확인하세요.

## 게임 동작

문제 수 3·5·10·15·20·30·40·50 중 준비된 수 이하를 선택합니다. 승인된 전체 문제은행을 Fisher–Yates로 섞은 뒤 선택한 수만큼 중복 없이 추출합니다. 한 게임의 최대 문제 수와 전체 문제은행 규모는 독립적입니다.

물건마다 두 번 추측합니다. 첫 오답에는 UP/DOWN과 거리 힌트를 표시하고, 첫 정답이면 즉시 결과로 이동합니다. 점수는 마지막 추측으로 계산하며 정확한 정답만 1,000점입니다. 시간 제한은 없습니다. 결과 복사, JSON 저장, 카카오·시스템 공유, 선택형 효과음, 전체 화면, 모바일 화면을 지원합니다.

새 세션은 출제 ID·순서·문제 스냅샷·해설·첫 추측을 저장합니다. 승인 목록이 바뀌어도 진행 중인 게임은 같은 내용으로 이어집니다. 예전 v2(시간 제한 없음)·v3 세션은 dist/legacy-data.json의 원래 순서로 복구하고 기존 랭킹 함수로 제출합니다. 예전 45초 모드는 복구하지 않습니다. 최고 기록은 기존처럼 문제 수별로 저장합니다.

## 데이터 구조와 반영

- content/candidates.json: 초기 후보와 새로 수집한 후보, 출처·가격 조건·품목별 확인 상태.
- content/images/: 후보의 로컬 원본 이미지와 갱신된 이미지 버전.
- content/review.json: 사람의 승인·보류·제외·메모와 물품별 제외/종류별 수집 이력. 저장과 게임 반영은 별개입니다.
- dist/data.json: 승인된 문제은행. 내용으로 bankVersion을 결정하므로 같은 내용은 같은 버전입니다.
- dist/legacy-data.json: 기존 10개 세트. 예전 이어하기를 위해 보존합니다.
- supabase/curation-v2.sql: ID 기반 채점 함수와 정답표를 추가하는 마이그레이션.
- supabase/curated-release.sql: 마이그레이션과 현재 승인 목록의 정답을 담은 자동 생성 파일.
- .artifacts/releases/: 이전 로컬 문제은행 백업. 이전 게임의 로컬 채점에 사용하며 Git과 배포에서 제외합니다.
- .artifacts/source-state.json: 품목군별 API 페이지·남은 후보·다음 수집 위치.
- .artifacts/source-backups/: 수집·갱신 전 후보와 사람 선택의 로컬 백업.

관리 화면과 같은 반영 작업을 터미널에서 실행할 수 있습니다.

```powershell
npm run content:apply
```

게임 데이터와 서버 정답을 손으로 각각 편집하지 마세요. 승인 목록에서 함께 생성합니다. 모든 정답은 해당 규격·단위·부가세·인도조건의 **등록 계약단가**이며 실제 구매·지급총액이 아닙니다. 상품 이미지·계약번호·순번·조회일·출처를 보존합니다. API 키와 개인 연락처를 배포하지 않습니다.

## 검사

수집은 최근 완료 조회가 20회 이상 쌓였을 때 최근 최대 30회 중 결과가 있던 비율이 10% 이하인 계약 유형의 우선순위를 낮추고, 아직 조회하지 않은 다른 물품명이나 결과가 있는 다음 페이지를 먼저 탐색합니다. 특정 계약 유형을 영구 차단하지 않으며 선택한 조회 상한을 유지합니다. 저장된 여러 종류 중에서는 제조사 비교 근거가 충분하고 가격 편차 경고가 적은 종류를 먼저 후보로 추가합니다.

게임과 선별 도구는 런타임 외부 패키지 없이 Node.js로 실행합니다. SQL 검사를 위해 개발 의존성 PGlite를 사용합니다. 처음 또는 잠금 파일 변경 후 설치하세요.

```powershell
npm ci --ignore-scripts
npm run check
```

기존 게임 검사에 더해 승인 목록과 게임·SQL 일치, 이미지 체크섬, 중복 없는 랜덤 추출, 이전/새 이어하기, 로컬 선별 HTTP와 테스트 랭킹, 공유 점수 텍스트를 검사합니다. PGlite의 실제 PostgreSQL 엔진에서 기존 랭킹 보존, 마이그레이션 재실행, 무작위 순서 채점, 잘못된 제출 거부, RLS와 공개 RPC 권한도 검사합니다. 운영 Supabase와 카카오 메시지 전송을 이 검사로 수행하지 않습니다.

## 운영 랭킹과 배포

기존 Supabase 프로젝트·공개 키·원래 랭킹 기록을 유지합니다. 신규 프로젝트라면 먼저 supabase/leaderboard.sql을 실행하고 dist/leaderboard-config.js에 Project URL과 anon/public 키를 설정합니다. service_role 또는 secret 키를 브라우저 파일에 넣지 마세요.

승인 목록 변경을 실제 사이트에 반영하는 순서:

1. 로컬에서 선택을 끝내고 **게임에 반영**합니다.
2. 선별실의 **운영 랭킹 SQL 내려받기** 또는 supabase/curated-release.sql을 열어, 기존 Supabase SQL Editor에서 실행합니다. 새 정답표·submit_score_v2·준비 상태 함수를 추가하며 기존 정답·함수·기록은 보존합니다. 재실행해도 같은 결과이고 한 트랜잭션으로 적용합니다.
3. 아래 두 검사를 실행합니다.

```powershell
npm run check
npm run check:release
```

check:release는 모든 출제 항목을 24시간 이내에 확인했는지 검사한 뒤, 운영 DB의 문제 수와 정답 지문을 현재 게임과 비교합니다. 점수 등록이나 DB 변경은 하지 않습니다. SQL이 아직 적용되지 않았다면 실패하는 것이 정상입니다.

4. 확인한 기능 브랜치를 푸시하고 PR을 통해 main에 병합합니다. GitHub Pages는 검사와 운영 정답 동기화 확인을 통과한 dist만 배포합니다. DB 준비가 안 됐으면 배포를 중단해 기존 공개 사이트를 유지합니다. 파일 주소에 커밋 버전을 붙이는 기존 캐시 갱신도 유지합니다.

랭킹은 문제은행 버전마다 하나이며, 기존처럼 문제 수와 무관하게 합산 점수로 정렬합니다. 기기별 첫 게임 기록만 등록합니다. 브라우저는 출제 ID와 추측값만 보내고 서버가 다시 채점합니다. 정답이 공개 데이터에 포함된 캐주얼 퀴즈이므로 경쟁형 대회용 부정행위 방지는 별도 범위입니다.

과거 문제은행 정답과 이미지는 삭제하지 마세요. 예전 이어하기와 기록을 유지하는 데 필요합니다. 가격은 조사 당시 스냅샷으로 표시하고 현재 판매 가격·구매 가능 상태로 주장하지 않습니다.
