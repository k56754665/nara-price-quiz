# 이게 얼마게? — 나라장터 가격 퀴즈

조달청 공식 API의 등록 계약단가를 맞히는 한국어 웹게임입니다. **2026-11-09 기준으로 선정한 104개 문제**에서 매 게임 10문제를 무작위로 출제합니다. 게임 중 나라장터 API를 호출하지 않습니다.

## 플레이 흐름

1. 나라장터에 등록된 실제 상품 사진·제품 이미지와 규격을 살펴봅니다.
2. 가격을 추측합니다. **정답의 ±10% 안이면 성공**입니다.
3. 틀리면 정답을 숨기고 UP/DOWN과 거리 힌트(조금·꽤·많이·아주 많이)를 표시합니다. 물건마다 **최대 3번** 추측합니다.
4. 정답·점수·틈새 지식을 확인하고 다음 물건으로 이동합니다. 틈새 지식은 물건과 별도로 매 게임 10개를 중복 없이 배정하며, 모든 라운드에 하나씩 표시합니다.
5. 최종 결과표에서 추측, 점수, 사진과 해설을 돌아봅니다.

점수는 몇 번째에 맞혔는지로만 정합니다: **1번째 1,000 · 2번째 800 · 3번째 500 · 실패 0**. 범위 안이면 정답과의 거리는 점수에 영향이 없습니다. 10문제 최고 10,000점이며 시간 제한은 없습니다. 규칙 값은 `dist/engine.js`의 `TOLERANCE_PERCENT`·`MAX_ATTEMPTS`·`ATTEMPT_SCORES`와 `supabase/rules-v3.sql`에 함께 있으며, 바꿀 때는 두 곳을 같이 고칩니다.

진행 중인 게임은 출제 순서·문제 스냅샷·가격·추측과 라운드별 틈새 지식의 순서·내용·출처를 브라우저에 저장합니다. 새로고침·이어하기나 지식 풀 갱신 후에도 배정은 유지되며, 정답 화면·최종 결과표·JSON 저장에서 같은 지식을 사용합니다. 기존 세션(v5)은 진행·점수를 보존하고 지식만 한 번 배정해 새 형식(v6)으로 저장합니다. 예전 규칙(두 번 추측)으로 하던 게임은 새 규칙으로 이어갈 수 없어 새로 시작합니다. 결과 복사, JSON 저장, 카카오·시스템 공유, 선택형 효과음, 전체 화면을 지원합니다. PC·모바일 가로 화면은 16:9 무대와 레터박스를 사용하고, 모바일 세로 화면은 기기 회전 안내를 표시합니다. 회전 후 진행 중인 게임과 열려 있던 정보 창을 이어서 볼 수 있습니다.

## 로컬 실행과 검사

정답이면 환호성과 관객·판사의 들썩임, 오답이면 “우우~”와 함께 살짝 내려가는 반응을 보여줍니다. 반응 뒤에는 하트 소모·재도전 힌트 또는 정답·획득 점수가 이어집니다. 채점과 진행 저장은 연출 시작 전에 완료하므로, 연속 제출·새로고침으로 점수가 중복 반영되지 않습니다. 효과음은 기본으로 켜져 있으며 메뉴에서 끄거나 켠 설정을 이 브라우저에 저장합니다. 시스템의 움직임 줄이기 설정에서는 이동·크기 변화 없이 판정과 점수를 표시합니다.

환호·야유는 로컬에 포함된 CC0 군중 녹음이며 출처와 편집 내역은 `dist/assets/audio/CREDITS.txt`에 있습니다. 효과음·판정 연출·저장 복구·모바일 검증은 `npm run test:effects`로 실행하고 `.artifacts/effects/`에 캡처와 검사 결과를 저장합니다. Playwright와 Chrome 경로 설정은 아래 UI 검사와 같습니다.

정답은 밝게 올라가는 네 음의 벨, 오답은 아래로 내려가는 세 음의 벨을 군중 소리와 함께 재생합니다. 오답 군중 반응은 사용자가 고른 C 시안, mrrap4food의 「crowd oh - - disappointed.mp3」(Freesound, CC0)을 적용하고 비교 시안보다 볼륨을 25% 낮췄습니다. 정답 군중 녹음은 1.60초·120ms 도입, 오답은 2.20초·80ms 도입으로 편집하고 모두 550ms에 걸쳐 부드럽게 마무리합니다. 자동 정답 공개·재도전 화면 전환에서도 잔향을 유지하며, 새 추측·사용자 화면 이동·음소거에서는 120ms에 걸쳐 정리합니다. `npm run test:audio`는 실제 오디오 그래프를 오프라인 렌더해 음높이 순서·도입/마무리·클리핑·중단을 검사하고 `.artifacts/feedback-audio/`에 정답·오답 WAV 미리듣기를 만듭니다.

정답 공개 화면에서는 실제 가격 강조가 시작되는 120ms 시점에 짧은 유리 반짝임 효과음을 한 번 재생합니다. 정답을 맞혔을 때와 세 번 모두 틀려 정답을 공개할 때 모두 같은 중립적인 공개음을 쓰며, 새로고침·이어하기에서는 반복하지 않습니다. 효과음 음소거와 화면 이동에 따른 정리도 기존 설정을 따릅니다.

벨이 군중에 묻히지 않도록 벨 음량을 높이고 울림을 늘렸습니다. 군중은 첫 벨보다 120ms 뒤에 들어와 벨 연주 중 낮게 유지되며, 이후 부드럽게 올라갑니다. 오디오 검사는 벨만 있는 파형과 전체 믹스를 비교해 벨의 음량이 군중보다 충분히 앞에 있는지도 확인합니다.

새 게임은 제공된 보랏빛 커튼 원본이 좌우로 열리고 라운드·상품이 차례로 등장합니다. 마지막 기회는 두 번째 오답 직후 남은 하트와 안내를 한 번 강조합니다. 정답 공개는 목재 패널·상품·실제 가격·점수 순서로 이어지고, 다음 문제는 짧은 퇴장과 등장으로 연결합니다. 커튼은 시작할 때만 재생하며, 이어하기는 연출을 반복하지 않습니다. 전환 중 입력을 잠시 막되 목적지 진행은 즉시 저장하므로, 전환 중 새로고침·회전에도 문제를 건너뛰거나 점수를 중복 반영하지 않습니다. 움직임 줄이기 설정에서는 커튼과 화면 전환 대기를 생략합니다.

현재 스코어와 UP/DOWN 말풍선은 원본 9-slice 배경을 화면 크기·픽셀 밀도에 맞춰 한 장으로 합성한 뒤 전체를 확대해 조각 사이가 갈라지지 않도록 합니다. UP/DOWN은 같은 말풍선 폭과 가로 여백을 사용하고, 긴 DOWN 글자는 UP의 여백 기준에 맞게 조절합니다.

최종 결과에서는 실제 총점 집계·등급 발표·점수별 캐릭터의 반응이 이어집니다. 이 기기 최고 기록을 엄격히 갱신하거나 10,000점 만점을 달성하면 팡파르와 소량의 색종이로 축하하며, 두 조건이 겹쳐도 한 번만 재생합니다. 결과 복구·이어하기에는 발표를 반복하지 않고, 발표 중 공유도 실제 최종 점수를 사용합니다. 타이틀 글자와 캐릭터의 대기 동작은 작게 반복하며 입력·안내 창·비활성 탭·움직임 줄이기 설정에서는 멈춥니다.

결과는 10,000점 **조달의 신**, 6,000~9,999점 **걸어 다니는 견적서**, 4,000~5,999점 **견적서 수사대 에이스**, 2,000~3,999점 **가격표와 밀당 중**, 0~1,999점 **가격표 앞에서 동공지진**의 다섯 단계입니다. 결과 화면과 ‘결과 자세히’에서 해당 설명을 표시하고, 공유에는 같은 등급을 사용합니다. 이미지는 `design-source/`의 Google Drive 원본 4종을 그대로 배포하며, 만점은 그물 든 새, 최저 구간은 같은 시트의 클립보드 다람쥐만 CSS로 표시합니다. 긴 설명은 작은 가로 화면에서 스크롤할 수 있고, 점수와 공유·다시하기 버튼은 항상 보입니다.

정답 순간에는 상품 프레임 양옆에 파랑·노랑 별과 점이 퍼지고, 오답은 방금 소모한 하트에서 붉은 점이 떨어집니다. 실제 가격은 공개음과 같은 120ms 시점에 옆에서 반짝이며, 성공한 라운드만 획득 점수 글자와 빛 점이 같은 곡선을 따라 현재 스코어 숫자 중앙으로 날아갑니다. 도착하면 숫자 둘레에 링이 나타나고 스코어가 한 번 커집니다. 최고 기록은 색종이 18개, 만점은 24개가 중앙 결과 패널을 피해 양옆에서 분사됩니다. 알아보기 쉽도록 초기 파티클보다 크기를 약 2~3배 키우고 표시 시간을 늘렸습니다. 900px 이하 무대는 수량을 절반으로 줄이되 정답·가격 반짝임 18px, 점수 점 10px, 하트 11px, 색종이 12px 이상의 기본 크기를 유지합니다. 장식은 화면 전환·회전·정보 창·비활성 탭·움직임 줄이기 설정에서 정리하며, 새로고침과 이어하기에는 반복하지 않습니다.

`npm run test:particles`는 PC 1920×1080·1366×768과 터치 모바일 에뮬레이션 844×390·667×375에서 P1 효과, 콘텐츠와의 겹침, 중복 재생·복구·회전·움직임 줄이기와 10문제 진행을 검사합니다. `.artifacts/particles/`에 효과를 샘플링한 캡처와 `verification.json`을 저장합니다. 효과별 범위와 후속 후보는 [파티클 효과 체크리스트](PARTICLE_EFFECTS_CHECKLIST.md)에 있습니다.

P2는 UP/DOWN 말풍선 옆의 방향 선, 실제 금액이 증가할 때 버튼 주변에 나타나는 점, 랭킹 첫 등록·기록 갱신 후 모달 안에서 나타나는 반짝임입니다. 금액 입력은 연타를 모두 반영하고 입자만 100ms 간격으로 제한합니다. 랭킹 반짝임은 성공 응답과 창 등장 뒤에 한 번 재생하며, 기존 최고 기록 유지·동점은 완료 테두리만 표시합니다. 실패·중복 등록·창을 닫은 뒤 도착한 응답은 축하를 재생하지 않습니다. `npm run test:particles:p2`는 같은 PC·모바일 네 크기에서 P2와 예외 상태를 검사하고 `.artifacts/particles-p2/`에 캡처와 결과를 저장합니다. 랭킹 요청은 전부 모의 응답을 사용합니다.

BGM은 사용자가 고른 C 시안, BlondPanda의 「Short Elevator Music Loop」(Freesound, CC0) 보사노바입니다. 공개 HQ MP3를 로컬에 포함해 외부 요청 없이 재생하며, 비교 시안과 같은 음량 보정과 반복 경계의 짧은 페이드만 적용합니다. 첫 조작 이후 한 곡만 이어서 재생하고, 환호·탄식·결과 발표음이 나올 때는 음량을 잠시 낮춥니다. 메뉴의 `BGM`과 `효과음`은 각각 켜기/끄기를 저장하며, 비활성 탭에서는 BGM을 정지하고 복귀 시 원래 위치에서 이어갑니다. 최종 결과·최고 기록·만점·BGM·대기 동작 검증은 `npm run test:results`로 실행하고 `.artifacts/results-effects/`에 결과와 캡처를 저장합니다.

```powershell
npm ci --ignore-scripts
npm run dev
```

`http://127.0.0.1:4173/`에서 플레이합니다. 서버는 `dist/` 아래 파일만 제공합니다. 랭킹 설정은 공개 사이트와 같으므로 실제 점수 등록은 운영 DB에 반영됩니다.

```powershell
npm run check
npm run check:release
```

UI 전체 검증은 `npm run test:ui`로 실행합니다. Playwright와 Chrome이 필요하며, 설치 위치가 다르면 `PLAYWRIGHT_MODULE`·`UI_BROWSER` 환경 변수로 경로를 지정할 수 있습니다. 이 PC에서는 Codex에 번들된 Playwright를 사용합니다. 독립 로컬 서버와 브라우저 저장소에서 10라운드, 가로 화면 11개 크기, 팝업, 회전과 오류 상태를 점검하고 `.artifacts/ui-audit/`에 캡처와 `verification.json`을 저장합니다. `UI_AUDIT_OUTPUT` 환경 변수로 출력 폴더를 바꿀 수 있습니다. 랭킹 등록·공유는 가로채서 모의 응답으로 검사하므로 운영 기록이나 실제 발송에 영향을 주지 않습니다. 실행 결과는 [UI 전체 점검 보고서](UI_AUDIT_REPORT.md), 기존 98장의 분류·시각 검수는 [UI 시각 검수 보고서](UI_VISUAL_REVIEW.md), PC·모바일 반응형 재구현과 확대 검증 결과는 [반응형 검증 보고서](UI_RESPONSIVE_REVIEW.md)에 있습니다.

게임과 정답표·이미지 출처의 일치, 체크섬, 무작위 중복 없는 출제, 이전·새 이어하기, PostgreSQL 채점·기존 랭킹 보존·잘못된 제출 거부·접근 권한을 검사합니다. PostgreSQL 검사는 개발 의존성 PGlite를 사용하며 운영 DB에 테스트 기록을 넣지 않습니다.

`check:release`는 확인 시각의 형식과 계약 유효기간을 확인하고, 운영 DB의 문제 수·정답 지문·채점 규칙 버전을 검사합니다. 확인 시각은 자료 이력으로 보존하며, 확인 후 경과 시간으로 배포를 제한하지 않습니다. 읽기 전용이며 운영 데이터는 수정하지 않습니다.

## 데이터와 이미지

- `dist/data.json`: 현재 104개 문제은행. `bankVersion`으로 버전을 구분합니다.
- `dist/trivia.json`: 물건과 독립적인 공통 틈새 지식 풀. 기준 시점·공식 출처를 포함한 서로 다른 지식을 최소 10개 유지합니다. `version`은 지식 내용 갱신 시 변경합니다. 새 게임에서만 추첨하므로 게임 사이에는 같은 지식이 다시 나올 수 있습니다.
- `dist/legacy-data.json`: 예전 10개 세트. 이전 이어하기와 기존 랭킹을 위해 보존합니다.
- `image-sources.json`: 현재 문제별 물품식별번호·모델·이미지 출처·원문 체크섬입니다.
- `supabase/leaderboard.sql`: 원래 랭킹 테이블·정답·채점 함수입니다.
- `supabase/curation-v2.sql`: 문제 ID로 무작위 출제를 채점하는 함수와 정답표 구조입니다.
- `supabase/curated-release.sql`: 새 채점 구조와 현재 문제은행 정답 104개를 함께 적용하는 SQL입니다.
- `supabase/rules-v3.sql`: 이전 규칙(±10% · 4번 추측) 채점 함수 `submit_score_v3`입니다. 기록은 `<문제은행 버전>:r3` 랭킹에 남아 있습니다.
- `supabase/rules-v4.sql`: 현재 게임 규칙(±10% · 3번 추측 · 회차별 점수) 채점 함수 `submit_score_v4`입니다. 기록은 `<문제은행 버전>:r4` 랭킹에 따로 쌓입니다.

계약번호·순번·규격·단위·인도조건·조회일을 보존합니다. 정답은 해당 조건의 **등록 계약단가**이며 실제 구매·지급총액이 아닙니다. 할인 정보는 정답 계산에 반영하지 않으며 해당 문제에 가격 기준을 표시합니다.

14개는 마지막 재조회가 API 호출 제한(429)으로 실패해 2026-11-09에 앞서 성공한 조회 스냅샷을 사용했습니다. 각 문제의 실제 `checkedAt`을 보존하며 재조회 성공으로 표시하지 않습니다. 현재 판매 가격이나 구매 가능 상태를 보증하지 않습니다.

상품 이미지는 물품식별번호에 연결된 공식 API의 `prdctImgUrl` 원문입니다. 공급업체가 등록한 제품 표현 이미지도 포함되며 유형을 데이터에 표시합니다. 원본을 수정하지 않았고, 게임에서 원본 링크를 제공합니다. 현재 문제와 이전 이어하기에 필요한 이미지를 함께 보존합니다.

API 비밀키, DB 비밀번호, 담당자 연락처, 인증이 포함된 요청 URL을 공개 파일에 넣지 않습니다.

틈새 지식은 `dist/trivia.json`만 수정하고 `npm run check`로 형식·개수·중복·출처와 저장·복구 동작을 검사합니다. 이 파일은 `dist/`와 함께 배포되며 문제은행 버전 계산에 들어가지 않습니다. 지식만 변경할 때는 `content/candidates.json`의 예전 `base.trivia`·물건별 `triviaId`나 문제은행을 재생성하지 않습니다. 이전 데이터는 보존하고 새 게임에서는 라운드별 배정만 사용합니다. Supabase 테이블·정답표·채점 함수의 추가 등록은 필요하지 않습니다.

## 온라인 랭킹 (Supabase)

게임은 기존 Supabase 프로젝트 **`wrcdxpoghhxejcvltvbe`**를 사용합니다. Project URL과 공개 키는 `dist/leaderboard-config.js`에 있습니다. 기존 프로젝트·공개 키·랭킹 기록을 유지합니다.

결과 화면에서 닉네임으로 기록을 등록하고 처음 화면의 **온라인 랭킹 보기**에서 TOP 20을 확인합니다. 문제은행 버전 + 규칙 버전마다 랭킹이 하나이며 10문제 합산 점수로 정렬합니다(동점이면 맞힌 문제 수). 매 게임 등록할 수 있고, 기기마다 최고 점수 하나만 남습니다(더 높을 때만 바뀜).

### 현재 104개 정답표 적용

1. **기존 Supabase 프로젝트**의 SQL Editor를 엽니다.
2. [`supabase/curated-release.sql`](supabase/curated-release.sql) 전체를 붙여 넣고 실행합니다. 기존 정답·함수·랭킹은 보존하고 새 문제은행의 정답과 채점 함수를 추가합니다. 한 트랜잭션으로 적용하며 재실행할 수 있습니다.
3. 이어서 [`supabase/rules-v4.sql`](supabase/rules-v4.sql)을 실행해 현재 게임 규칙의 채점 함수를 추가합니다. 재실행할 수 있습니다.
4. `npm run check:release`로 운영 DB의 정답 104개·게임 규칙과 로컬 문제은행이 일치하는지 확인합니다.
5. 실패했던 GitHub Pages 배포를 다시 실행하거나 검증한 변경을 `main`에 푸시합니다.

DB를 다른 개발자가 관리한다면 2번의 SQL 실행을 그 개발자에게 요청하면 됩니다. 직접 DB에 접속하려면 DB 비밀번호와 연결 주소가 필요합니다. IPv4 환경에서는 Supabase 대시보드의 **Connect → Session pooler**에 표시된 연결 주소를 사용합니다. 비밀번호나 전체 인증 주소를 README·공개 코드에 넣지 마세요.

### 빈 프로젝트를 처음 설정할 때

기존 게임을 갱신할 때는 새 프로젝트를 만들 필요가 없습니다. 별도의 빈 프로젝트를 구성할 때만 아래 절차를 사용합니다.

1. Supabase에서 프로젝트를 만듭니다.
2. SQL Editor에서 [`supabase/leaderboard.sql`](supabase/leaderboard.sql)을 먼저 실행합니다.
3. 이어서 [`supabase/curated-release.sql`](supabase/curated-release.sql), [`supabase/rules-v3.sql`](supabase/rules-v3.sql), [`supabase/rules-v4.sql`](supabase/rules-v4.sql)을 차례로 실행합니다.
4. 프로젝트의 Project URL과 publishable 또는 legacy anon/public 키를 `dist/leaderboard-config.js`에 넣습니다. 브라우저 공개용 키만 사용하고 `service_role`·secret 키는 넣지 않습니다.
5. `npm run check`와 `npm run check:release`를 통과한 뒤 배포합니다.

### 채점과 기록

브라우저는 출제 ID와 추측값만 보내며 Supabase가 정답표로 다시 채점합니다. 테이블은 RLS와 권한으로 제한하고 공개 랭킹 함수만 호출할 수 있게 합니다. 예전 게임의 정답·함수·기록은 보존합니다.

정답이 공개 데이터에 포함되는 캐주얼 퀴즈이며 경쟁형 대회용 부정행위 방지는 별도 범위입니다. 이상 기록은 프로젝트 관리자가 `leaderboard_scores`에서 확인할 수 있습니다.

## 배포

`.github/workflows/pages.yml`은 `main` 푸시 또는 수동 실행에서 검사하고 `dist/`만 GitHub Pages에 배포합니다. GitHub 저장소의 **Settings → Pages → Source → GitHub Actions**를 설정해야 합니다.

운영 DB의 정답표가 아직 준비되지 않았으면 배포를 중단하고 기존 공개 사이트를 유지합니다. 성공한 배포의 주소는 **Actions → Deploy game to GitHub Pages**에서 확인합니다. 배포마다 CSS·JS·데이터 주소에 커밋 버전을 붙여 캐시를 갱신합니다.

배포 산출물에는 `.env.local`이나 DB 비밀번호가 필요하지 않습니다. 가격은 조사 시점의 스냅샷으로 표시하며 공개·촬영 전 원본 계약 정보를 확인하세요.
